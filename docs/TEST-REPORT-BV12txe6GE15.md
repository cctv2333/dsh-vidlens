## 二、问题清单

### R-1 `[必修]` 转写按 20 秒死块切，句子被切断、时间码只有 20s 粒度

**怎么感觉到的**
- brief 的转写区每 `20.000`s 一行，读数感像被剪刀剪过：
  - `08:00` 行结尾是"更有意思。"，`08:20` 行开头是"指的是,1972年…"——"更有意思的是"被拆到两块里；
  - `08:40` 行开头是"成变化,"（"发生变化"的后半）。
- 问"他哪一秒说过 X"做不到：`seek("教援")` 只给 `08:20.000`，真实发音可能在 08:20–08:40 任意位置。
- 碎片还会**伪装成内容含糊**：`02:00` 行以"化长鬼呢"开头，我第一轮把它读成"作者表述跳跃"，实际画面上写的是"资产阶级代言人和学术文化**伥鬼**呢"。

**根因（已定位）**
- `vidlens_sensevoice.py:73` `CHUNK_SECONDS = 20.0`；`:171` `step = max(1, int(chunk_seconds * sr))` 非重叠切块，每块单独解码，文本按块挂时间码。
- 所以时间码精度 = 块长 = 20s；句子边界 = 块边界，与语义无关。

**修法（观点，按性价比排序）**
1. **最省事**：把 `chunk_seconds` 暴露成 `video_brief` / `video_window` 的参数（现在签名里没有），专名密集的政论/历史片由调用方降到 10s，不动任何默认行为。
2. **中等**：20s 块 + 1s 重叠，重叠区用后缀/前缀最长公共子串去重。改动只在 `transcribe()`，不动缓存结构。
3. **最正**：VAD（能量或 SenseVoice 自带的时间戳）找语音段边界再切，段长 3–8s；失败回退固定块。
4. 展示层兜底：按标点把相邻块合并成句，时间码取句首块起点并标注"≈"。

**风险与坑**
- **会动缓存契约**：`transcript.jsonl` 的 rows 若新增字段（词级时间、段置信度），已有 19 个缓存视频要么迁移、要么读旧格式。建议：只加字段不删字段，`info` 里追加 `chunk_seconds`，旧缓存按原样读、不重跑。
- **重叠去重容易误删**：中文连续语音里"的/是/就"高频，最长公共子串策略会把正常重复词吃掉；必须限制"只在重叠窗口内、且长度 ≥ 阈值"才去重。
- **VAD 在音乐段会漏切**：本片 SenseVoice 的 event 有 Music 标签，纯 BGM 段落 VAD 找不到语音边界，会退化成整段一块。
- **成本线性上涨**：14 分钟约 44 块，20s→10s 就是 88 块，ASR 时间大致翻倍。上默认值前要实测"14 分钟片 < 60s"这条线还在不在。
- **别承诺词级**：改成 VAD 后时间码仍是"段起点"，不是词级；文档里不要说成"精确到秒"。

**验收**
- 同一片重跑：转写行不再以"指的是,"/"成变化,"这类纯连接词开头；
- `seek` 命中时间码与人工听检误差 ≤ 5s；
- 旧缓存（19 条）读出来不报错、不重跑。

### R-2 `[必修]` 20 分钟以内的无切点视频，`video_plan` 仍标"章节"，且"视频不长"这句永远打不出来

**怎么感觉到的**
- 14:41 的片子，返回"章节 3 个（窗口约 300s）"，三段正好 `0–300 / 300–600 / 600–881.8`——等分，不是叙事转折。本片真正的转折很清楚（06:00 极权主义、09:00 伯林、12:20 国家理论），一个没抓到。
- 更别扭的是：14:41 **不到 20 分钟**（`LONG_VIDEO_SECONDS = 1200`），本该提示"视频不长，一次读完即可"，实际却按长视频姿态列章节。

**根因（已定位）**
- `vidlens_web.py:909-916`：没有 cuts、没有 ≥2s 长静音时，按 `window` 补固定网格——代码注释自己写了"免得生成一个 40 分钟的章节"，说明这是**已知的网格回退**。
- `vl_mcp.py:480-485`：分流条件是 `if len(ch) <= 1:`。只要 `dur > window`，`len(ch)` 必然 ≥2，所以：
  - `dur ≤ 1200` 且无切点 → 仍然列表格（本条片子）；
  - `dur > 1200` 且无切点 → 走到"按固定窗口分段"（B-017 修过的那侧）。
- 即：**B-017 只修了 >20 分钟那一半，对称的 ≤20 分钟没修**；判断维度也还是章节数，不是时长。

**修法（观点）**
- 分流改成看时长 + 有无切点数据：`dur <= LONG_VIDEO_SECONDS && not cuts && not gaps` → 直接说"视频不长（14:41），一次 `vidlens_brief` 读完即可；要分段可传 `window=120`"。
- 网格段的措辞改掉：标题不叫"章节 N 个"，叫"分段 N 个（无切点，按 300s 网格）"，每行标 `(grid)`。

**风险与坑**
- 仓库里有自检/回归断言可能钉住了"章节 N 个"这句（请先 `grep -r "章节 " tests/`）；改文案会连带改基线。
- `vl plan`（CLI）与 MCP 共用 `video_plan`，改了 CLI 输出也会变；CLI 的 `vl clip --from/--to` 示例还写在 brief.md 里，别一起改坏。
- 别把 1200 写死，用现成常量；`MIN/MAX_CHAPTER_WINDOW`（60/3600）已经在 `vl_mcp.py:113-114`。

**验收**
- 同一片：`vidlens_plan` 输出"视频不长，一次读完即可"，或明确标 `(grid)`；
- 40 分钟片（B-016/B-017 的用例）行为不回退。

### R-3 `[文案]` 回执里的下一步提示是 `video_*` 旧工具名，本通道叫 `vidlens_*`

**怎么感觉到的**
- brief 第一段："覆盖: 音频 ✓ · 画面 ✗（要画面用 `video_visual_scan`）"；
- brief 末尾："`video_window(start,end)` 读某段台词 · `video_sheet` 看某段画面 · `video_brief(level="full")`"；
- `brief.md` 里："`vl grab --cuts`"、"`vl clip <url> --from …`"；
- plan 末尾："每段用 `video_window` 读台词、`video_sheet` 看画面"。
- 但**同一份输出里**，`vidlens_seek` 的回执写的是"用 `vidlens_window` 取上下文"——两套名字并存。

**根因（已定位）**
- 文案硬编码在工程本体：`vl_mcp.py:632`、`vl_mcp.py:665`、`vidlens_web.py:983`。这些是旧 MCP surface 的工具名。
- DSH 桥直接复用同一批函数（`bridge/vidlens_bridge.py:448-455` 的 TOOLS 映射到 `vl.video_*`），于是把旧名字原样带进 `vidlens_*` 通道。
- 插件侧 `index.js` 有正确的系统提示词（`:717-748`），但**工具返回值里的字面量不会经过它**。

**修法（观点）**
- 不要全局改名——另一个 surface 的工具真叫 `video_*`，改了会把那边改坏。
- 方案 A（推荐）：核心包只说动作，不说工具名（"要看画面：sheet / frames"），前缀由 surface 拼。
- 方案 B：给 `build_brief`/`_digest` 传 `tool_prefix`（`""` 或 `"vidlens_"`），默认 `""` 保持旧行为，桥传 `"vidlens_"`。
- 两种都要顺手处理 `brief.md` 落盘文本（`vidlens_web.py:983`）。

**风险与坑**
- 字符串散在 3 个文件 + 落盘 md；历史缓存里的 brief.md 会保留旧名，**别做迁移**，接受不一致。
- CLI 命令是 `vl xxx`，与工具名不是一套，改前缀时别把 `vl clip` 也一起替换。
- `_digest` 的返回文本有长度预算（B-050），加前缀会变长几个字符，注意别顶破摘要字数上限。

**验收**
- `grep -n "video_window\|video_sheet\|video_visual_scan\|video_brief" vl_mcp.py vidlens_web.py` 在"给模型看的提示"里清零；CLI 语境保留。

### R-4 `[建议]` `vidlens_library` 有脏记录、重复缓存

**现象**：19 条里 2 条 `0.0MB`；一条 `(无标题) · 00:00.000 · 139 段`；`BV1cVn86BEwd` 与 `BV1cVn86BEwd_p1` 同时存在（2.97MB / 0.73MB）。
**根因**：`tool_library` 只按目录/文件存在性汇总（与 `docs/ISSUES.md` I-009 同源）；分 P 与主视频各自成目录。
**修法（观点）**：每条加 `has_media` / `has_transcript` 标记；0.0MB 标 `incomplete`；分 P 与主视频用 `bvid + cid` 归并成一条（不要按标题归并）。
**风险**：按标题归并会把"同名不同片"吃掉；改成按 bvid 归并又会让分 P 结构丢失——输出里要保留 `p1/p2` 子项。

---

### R-5 `[建议]` `vidlens_comments` 的 `limit` 是近似值

**现象**：传 `limit=30`，回 36 条。
**根因**：`vidlens_extra.py:315-317` `ps = min(20, limit)`，按页取，`:351` 到 `limit` 就 break，页粒度导致超出。
**修法（观点）**：取完切片到 `limit`，回执注明"共抓 N 条（按页取，可能略多）"。
**风险**：高赞评论是单独拉的，切片别切错对象（先切"最新"，再拼"高赞"）。

### R-7 `[建议]` 有硬字幕时，brief 不知道（这条最容易误伤结论）

**现象**：本片全程硬字幕，`vidlens_ocr` 40 秒读出来一字不差；但 brief 只走 ASR，于是：

| 画面硬字幕 | ASR |
|---|---|
| 伥鬼 | 长鬼（整句塌成"化长鬼呢"） |
| 以赛亚·伯林 | 以萨亚柏林 |
| 麦卡锡主义 | 麦卡西主义 |
| 教员 | 教援 |

**判断**：这不是 bug（`video_brief` 从没承诺读硬字幕），是**能力没用上**。
**修法（观点）**：ASR 收尾时抽 3–5 帧跑一次 OCR；若字幕行命中率超阈值，在 brief 顶部加一行"检测到硬字幕，专名可用 `vidlens_ocr` 校订"，或直接做专名替换（保守：只替换"高频专名 + OCR 高置信"）。
**风险**：OCR 会把台标/字幕条/演职员表当字幕（本片实测丢弃了 1 类静态叠加层，说明已有过滤，但换片不一定）；自动替换专名一旦错，比不替换更坏——建议先只给提示，不自动改。

## 三、为什么我"没看全"——这是产品线索，不只是我的锅

1. **默认就是抽样**：`vidlens_brief` 给 digest（5 句关键句 + 全文路径），这是 B-050/B-051 刻意压上下文的设计。我顺着设计走没错，**错在我把抽样当全片下了结论**。
2. **5 句是"均匀取样"，恰好跳过论证骨架**：本片的骨架在每段的首句/结论句（06:20 阿伦特、09:00 伯林、12:20 国家理论），均匀取点取到的是中段细节。我据此写"弱点"，其中一条（"回避了阿伦特写作的纳粹经验"）被 06:20 的原文直接打脸——原文写了"通过纳粹德国与斯大林时期的苏联研究"。这条不是工具骗我，是我用先验补了没读到的部分。
3. **ASR 错字让我读到的是残缺文本**：我把"化长鬼呢"读成"表述含糊"，而不是"转写错误"。画面硬字幕一直摆在那儿，我到第二轮才去 OCR——**交叉验证做晚了**。
4. **画面只抽了 80 秒（9 格）+ 2 帧**，却对"制作水准/节奏"下了判断。覆盖率那行我写了"画面 ✗"，但"弱点"部分越过了这个边界。

**工具侧可优化（观点）**
- digest 的 5 句改成"按段落转折取"（每段首句 + 结论句），比均匀取样更能支撑"评价内容"这个任务；
- `vidlens_brief(level="skeleton")`：只给骨架（章节 + 每章一句论点，约 400 字），比 digest 更适合"这视频讲了什么、值不值得看"；
- 每句关键句标证据强度（有硬字幕可对照 / 纯 ASR / 有画面佐证）；
- 一行字提示"本片疑似有硬字幕"——就能让我知道该去 OCR。

**使用侧（我自己的纪律）**
- 评价内容前先抽 3 帧看有没有硬字幕；
- 对"制作水准"下判断前至少看 3 张拼图（25% / 50% / 75%），不是只看开头；
- 结论里显式标注"哪一条基于抽样"。

## 四、优先级（观点）

| 优先级 | 条目 | 理由 |
|---|---|---|
| P1 | R-1 分块 | 唯一会**系统性污染内容判断**的问题；错字/断句会被读成"作者表述含糊" |
| P2 | R-2 plan 分流 | B-017 的对称缺口，20 分钟以内是绝大多数视频，误导面最大 |
| P3 | R-3 命名 | 不改会让模型去找不存在的工具，改了有跨 surface 风险，需先定方案 |
| P4 | R-7 硬字幕提示 | 收益高但属增量能力，先做"提示"不做"自动替换" |
| P5 | R-4/R-5/R-6 | 体验与数据卫生 |
